# ACPlugin 插件规范草案

状态：设计记录。当前 0.2.2 只提供管理员插件中心的 UI 壳子，不实现目录连接、插件安装、插件执行、上传持久化或后端 API。

## 目标与边界

- ACPlugin 是 ArtiChat 的官方插件目录。目录项目由 ArtiVis 发布并在进入目录前完成验证。
- 管理员插件中心负责查看目录状态、管理安装状态、控制插件开关，以及提供个人上传入口。
- 用户上传的插件只属于上传用户本人，不进入社区目录、不进入其他用户的列表，也不进入管理员审核队列。
- 网页引用、工作区导出、代码审阅器等 ArtiChat 内置能力不作为插件展示。
- 插件不可用、目录离线或插件执行失败时，不得阻塞聊天、登录、订阅、用量和其他核心流程。

## 插件状态

插件状态是服务端权威字段，UI 不得仅凭客户端状态把插件变成可用：

- `development`：开发中，只展示信息，安装、启用和模型调用入口均不可用。
- `catalog`：已通过 ACPlugin 验证，可展示版本、权限和兼容性信息，但尚未安装。
- `installed_disabled`：已安装但默认停用，不能被模型调用。
- `enabled`：已安装并通过权限确认，可以按声明的权限运行。
- `update_available`：存在新版本，继续使用旧版本直到管理员明确升级。
- `quarantined`：校验、签名、权限或运行时检查失败，只能查看失败原因，不能加载。

当前唯一展示的邮箱助手必须保持 `development`，不可安装、不可启用、不可被模型调用。

## Manifest 最小字段

插件包根目录必须包含 `.acplugin/manifest.json`。字段命名以 `acplugin_manifest_version` 为准：

```json
{
	"acplugin_manifest_version": 1,
	"id": "com.artivis.email-assistant",
	"name": "邮箱助手",
	"version": "0.1.0",
	"host_api": ">=0.2.2 <0.3.0",
	"description": "插件用途说明",
	"author": "ArtiVis Labs",
	"entry": "src/index.js",
	"permissions": [],
	"compatibility": { "platform": ["server", "desktop"] },
	"integrity": { "algorithm": "sha256", "digest": "..." },
	"signature": { "algorithm": "ed25519", "key_id": "acplugin-release-1", "value": "..." }
}
```

约束：

- `id` 全局唯一且稳定，不能复用已下架插件的身份。
- `version` 使用 SemVer；升级必须提供迁移说明和可回滚版本。
- `entry`、权限、兼容性和完整性信息必须在安装前可见。
- Manifest 不得包含密码、API key、session token 或其他凭据；凭据只能由宿主的安全存储提供。
- 未通过 JSON Schema、完整性和签名校验的包不得安装或执行。

## 权限模型

权限采用声明式、最小授权、默认拒绝：

- `model.context`：读取经过筛选的模型上下文。
- `mail.send`：提交邮件发送任务；必须由宿主执行收件人约束、用户确认、频率限制和审计。
- `network.request`：访问明确的网络目标，默认无权访问任意地址。
- `workspace.read` / `workspace.write`：访问工作区，必须限制到授权路径。
- `files.read` / `files.write`：访问用户文件，必须逐次校验路径和大小。
- `schedule.create`：创建自动化任务，必须单独展示同意和撤销入口。

插件只能使用 Manifest 中声明的权限。权限变化视为需要重新确认的升级，不能静默扩大权限。

邮箱助手未来实现时必须使用当前认证用户的已验证邮箱作为收件人，不能由模型自由指定收件人、CC 或 BCC；这条规则属于宿主能力，不交给插件自行绕过。

## 上传、安装与运行

1. 上传包先进入当前用户的隔离暂存区，完成大小、格式、Manifest、依赖、签名和恶意内容检查。
2. 个人上传记录只与当前用户关联，不出现在 ACPlugin 目录和其他用户视图中。
3. 安装前显示版本、作者、权限、兼容性、签名状态和数据访问范围；校验失败进入 `quarantined`。
4. 新安装默认为 `installed_disabled`；只有管理员或拥有明确权限的用户主动启用后才可运行。
5. 插件应在受限 worker/沙箱中运行，具备超时、资源上限、崩溃隔离和可撤销开关。插件异常只能终止本次插件任务，不能终止聊天请求或主进程。
6. 卸载必须移除可执行内容并保留必要的审计元数据；卸载不能删除用户聊天、订阅或用量数据。

## ACPlugin 目录同步

- 目录连接由管理员配置，UI 必须能明确表达 `未连接`、同步中、同步成功和同步失败。
- 目录不可用时保留当前已安装插件状态，不清空本地数据，不阻塞核心页面。
- 同步只更新签名元数据和版本索引；插件包下载、校验和安装是独立步骤。
- 目录项目必须可追溯到发布者、版本、摘要和签名 key id。

## 更新、回滚与审计

- 每次安装、启用、停用、升级、回滚、卸载、校验失败和运行失败都记录操作者、插件 ID、版本、权限摘要和结果。
- 升级前保留上一个可运行版本；健康检查失败自动回滚到上一个版本并停用新版本。
- 任何插件都不能写入 ArtiChat 的核心用户、订阅、用量或聊天表；需要业务数据时使用插件命名空间和宿主 API。
- 审计记录不得保存插件凭据、原始认证请求或敏感邮件正文。

## 当前版本验收标准

- 访问 `/admin/subscriptions/plugins` 只对管理员开放。
- ACPlugin 当前显示 `未连接`；不存在目录连接时，普通聊天和其他管理员工具照常可用。
- 邮箱助手显示 `开发中`，没有可点击的安装、启用或调用入口。
- 个人上传入口只产生当前用户范围的本地 UI 状态；当前版本不上传、不持久化、不执行文件。
- 页面不展示内置能力为插件，不调用未实现的插件 API。

后续实现必须先以本规范为准补充 JSON Schema、签名公钥轮换、沙箱技术选型、宿主 API 版本和后端数据模型，再接通 ACPlugin 目录。
