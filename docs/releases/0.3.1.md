# ArtiChat 0.3.1

ArtiChat 0.3.1 是一次安全性、媒体生成体验和管理端界面更新。版本在保留订阅计费、媒体任务、自动记忆、邮件访问限制和中文产品行为的基础上，完成了 Open WebUI 上游安全修复的选择性回补，并把图片/视频生成状态整理为可恢复的生命周期。

本版本已按用户授权发布到 GitHub；发布流程只更新 GitHub 提交、版本 Tag、GHCR 镜像和 Release，不自动部署生产环境。

## 本次重点

- **图片与视频生成体验**：图片生成、图片编辑和视频生成统一显示生成中状态；成功后由占位卡直接替换为返回的媒体，失败时移除占位卡并保留模型说明。媒体结果按工具调用关联，避免同一文件重复显示；切换会话或 Socket 重连后，已保存的生成状态可以恢复。
- **图片提供商管理**：管理员可以在图片设置中分别测试生成和编辑连接。测试请求使用最小请求体或内存中的测试图片，结果不会保存；API Key 等敏感字段在管理端响应中会被遮蔽，保存遮蔽值时保留原密钥。
- **知识库与检索安全**：模型挂载文件和知识库检索重新执行文件读取权限检查；Qdrant 检索与删除应用租户和过滤条件，非法过滤操作默认拒绝。
- **SSRF 与资源边界**：统一检查 URL、重定向目标、IP 字面量和 DNS 解析结果，覆盖私有地址、IPv4 映射地址和 CIDR 过滤；网页下载改为流式大小限制，并限制提取元数据和工具服务器规格响应的体积。
- **身份与访问控制**：OAuth/SCIM 标识匹配改为精确 JSON 路径匹配，OAuth Token Exchange 使用与浏览器回调一致的角色策略；记忆注入、频道消息、文件、文件夹和模型相关路径补充权限校验，文件夹移动拒绝自循环和跨用户父级。
- **终端预览隔离**：终端端口预览默认不授予 `allow-same-origin` 和 `allow-forms`，只有显式接口设置才会放开。
- **性能与稳定性**：文件夹树、频道列表、未读数、成员和私聊用户读取改为批量查询；媒体文件事件合并并去重，工具状态和结构化输出不会重复展示媒体工具细节。
- **界面与运营工具**：更新侧栏导航、搜索入口、资产中心入口、用户菜单、免费用户升级与订阅设置界面，并继续完善管理员更新、订阅和图片配置页面。
- **ArtiAPI 接入**：在管理员“外部连接”页面增加 ArtiAPI 卡片，内置连接地址，填写密钥即可接入；支持新增多个密钥、分别启用和选择模型，提供官网入口，并适配黑白主题。

## 兼容性与安全

- 保留现有 `artichat_data` 数据卷和生产端口约定；升级前请停止写入并备份数据卷。
- 本版本没有把 Open WebUI 0.11.3 做整树合并，而是按 ArtiChat 的计费、媒体、记忆、邮件和访问限制契约选择性回补。
- 图片提供商测试按钮会向配置的上游服务发出真实请求，可能产生供应商费用；未授权时不要点击测试。
- 生产环境请继续固定并长期保留 `WEBUI_SECRET_KEY`，并在升级后确认 `/health` 和 `/ready` 返回成功。
- 镜像构建支持发布流程中的 Debian 镜像参数，默认使用官方 HTTPS 地址，并保留下载缓存、重试和传输超时。

## 更新方式

- 管理员可在“设置 -> 更新”检查 GitHub 稳定版本并查看版本说明。版本检查是管理员主动打开或刷新页面时执行的，不会向所有普通用户建立后台推送连接。
- “立即更新”只对已配置 `ARTICHAT_UPDATE_GITHUB_TOKEN`、版本仓库、GitHub Actions 部署工作流和受限 SSH 更新 runner 的实例开放。其他自部署实例仍可手动拉取 GHCR 固定版本镜像；如需一键更新，必须为该实例配置自己的仓库、镜像和 runner。
- 更新脚本会先检查本地持久化范围、备份数据、固定版本镜像并在健康检查失败时回滚；外部数据库、向量库或对象存储未完成独立备份时会拒绝自动更新。
