# ArtiChat 0.2.1

ArtiChat 0.2.1 以 Open WebUI 0.11.0 为新基础，完成订阅计费、权限、运营工具和推理控制的系统性重建。该版本支持从已发布的 0.1.7 直接升级，无需安装未发布的 0.2.0。

## 主要更新

- 升级到 Open WebUI 0.11.0 基础，保留 ArtiChat 品牌、订阅和四类 Token 计费能力。
- 重建订阅计划、模型访问、兑换码、礼品卡、公告和全局 Usage Ledger 等运营工具。
- 恢复 Plan / Check 余额、请求预留与幂等结算，完善失败释放、跨周期记账和审计明细。
- 提供 Low、Balanced、High、Ultra、Max 五档推理强度，并按模型提供商映射到正确请求参数。
- 收紧文件、图片、RAG、语音、嵌入、Web 搜索、BYOK 和管理员生成接口的权限边界。
- 新增合并迁移、启动失败保护和 `/ready` 数据库就绪检查，当前 Alembic head 为 `c3d4e5f6a7b8`。
- 更新个人订阅、用量、兑换与礼品入口，以及 Platform、Email、Update 和 About 设置界面。
- Docker Compose 使用稳定命名卷，并在数据卷内持久化应用密钥文件。

## 从 0.1.7 升级

1. 停止 0.1.7 服务，避免升级备份期间继续写入。
2. 完整备份 `artichat_data` 命名卷并验证归档可读取。
3. 拉取 `main` 的 0.2.1 提交，执行 `docker compose -p artichat up -d --build artichat`。
4. 确认 `/health`、`/ready` 和 `/api/version` 均正常，再恢复外部流量。

已使用生产数据的只读复制卷验证 0.1.7 直接迁移到 0.2.1、重启幂等性、主数据库与 Chroma 数据保留，以及把升级前归档恢复到 0.1.7 的完整回滚流程。

回滚时必须把升级前归档恢复到干净数据卷。不要让 0.1.7 直接连接已经迁移到 0.2.1 的数据卷。

## 验证摘要

- 依赖完整的后端测试：306 项通过。
- 迁移就绪测试：11 项通过。
- 生产前端构建、版本、品牌、更新与订阅守卫通过。
- 空数据卷启动和 0.1.7 生产复制卷直升通过。
- 桌面端与移动端 Operations、Usage Ledger 和 About 验收通过，无页面错误或 HTTP 5xx。

## 兼容性

- 推荐 Docker 20.10+、Docker Compose v2 和至少 4 GB 内存。
- 当前基础平台为 Open WebUI 0.11.0。
- 超过 50 名用户或用于商业用途时，请遵循 Open WebUI 许可协议并向其官方获取授权。
