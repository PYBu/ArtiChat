# ArtiChat 0.2.4 Update-System Repair (2026-08-05)

## Scope

- Fix the admin update panel appearing connected while silently treating a missing update repository as "up to date".
- Make disabled checks, missing repository configuration, and GitHub failures visible in the update response.
- Provide the official `PYBu/ArtiChat` repository as the application and production Compose default.
- Make the AWS/1Panel deployment runner derive `ghcr.io/pybu/artichat` when no image repository is configured.
- Bump the application version to 0.2.4 for the repair release.

## Implementation

- `backend/open_webui/env.py` defaults `ARTICHAT_UPDATE_REPOSITORY` to `PYBu/ArtiChat`; `ENABLE_VERSION_UPDATE_CHECK=false` remains the explicit offline opt-out.
- `ArtiChatUpdateService` now carries an enabled flag and returns explicit error text for disabled checks or a missing repository. Deployment rejects disabled checks before dispatch.
- The admin update router avoids constructing a GitHub client while checks are disabled. The legacy `/api/version/updates` response now includes `update_available` and `error` fields.
- `.env.example` and production Compose use the official repository default. `artichat-deploy.sh` derives the image repository from the configured update repository or its official default.
- Added focused update-service/router coverage and a deployment-runner default-repository case. Static update-system guard now protects the defaults and explicit error behavior.
