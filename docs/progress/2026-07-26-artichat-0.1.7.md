## Confirmed Product Decisions

- 0.1.7 centers on per-message reasoning-effort control.
- The composer control is opt-in per model. The model editor has a switch that enables or disables it.
- Provider behavior is never inferred from the Base URL hostname.
- The administrator explicitly selects the saved reasoning family/profile. Model-ID matching may only suggest a default.
- GPT/Codex and Claude use separate labels, colors, and request mappings.
- Both profiles use five levels. `Max` is the strongest level; `Ultra` and `UltraCode` are excluded.
- GPT/Codex labels: `Low`, `Medium`, `High`, `Extra High`, `Max`.
- Claude labels: `Low`, `Medium`, `High`, `Extra`, `Max`.
- New chats start at `High`.
- The control sits beside the composer integrations button.
- The slider follows the pointer while dragging and snaps to the nearest level on release.
- Increasing the level flips the label upward; decreasing it flips the label downward.
- GPT uses neutral gray through High, then increasingly saturated blue. Claude follows the same pattern with purple.
- Max uses restrained animation with a backward energy sweep, short streaks, distance-preserving pixel pulse, handle pulse, and short shock wave. The composer button itself has no animation.
- Reduced-motion users receive a static state.
- The desktop popover is compact (`344px` wide and about `134px` high); mobile uses a bottom sheet with `14px` side margins.
- A selected level is captured when the user message is submitted. Changes during generation affect only the next request.
- Queued messages capture their model and reasoning level when enqueued.
- Switching between enabled GPT and Claude models preserves the level position and changes the family label. Unsupported models hide the control.
- Multi-model chat hides the control in 0.1.7 and uses each model's configured default behavior.
- Regeneration uses the current slider level. Continue-generation retains the original response level.
- New responses retain the effective level in message metadata.
- When enabled, the new model control owns reasoning selection and replaces the legacy free-text editor for that model. Disabled models retain legacy behavior.
- The browser sends only an internal ArtiChat level. The backend validates it and maps it using the saved administrator profile.
- Native outbound Anthropic `/v1/messages` support is deferred; the current upstream receives Responses requests and performs its own conversion.

## Current Code Facts

- The connection editor selects Chat Completions or Responses.
- Responses already has message, tool, stored-output, streaming-event, and non-stream conversion paths.
- The existing advanced setting exposes `reasoning_effort` as unrestricted text.
- The Responses converter currently leaves `reasoning_effort` at the top level instead of producing `reasoning: { effort: ... }`.
- Chat controls are stored at conversation level, and queued requests currently capture only prompt and files.
- Model inference params are applied after request params and can currently override a per-request reasoning value.
- Normal outbound chat does not natively send Anthropic Messages requests.

## API Constraints

- Reasoning levels are model-specific and must not be sent blindly to every model.
- GPT mapping: `low`, `medium`, `high`, `xhigh`, `max`.
- Claude mapping: `low`, `medium`, `high`, `xhigh`, `max` on supported models.
- Chat Completions receives top-level `reasoning_effort`; Responses receives nested `reasoning.effort`.
- Existing external API clients using standard reasoning fields must remain compatible.

## Implementation Direction

- Store a validated reasoning-control object in model metadata with `enabled` and `profile` fields.
- Use stable internal levels `low`, `medium`, `high`, `extra`, and `max`; family-specific labels stay in the frontend.
- Persist the internal level on the user message and effective profile/level on the assistant response.
- Resolve the upstream literal server-side from the selected model's saved profile.
- Keep legacy `reasoning_effort` behavior only when the new control is disabled.
- Treat unknown profiles, levels, or unsupported multi-model requests as explicit validation cases; never silently downgrade Max.
